feat(tools): 补齐 web_search / web_fetch / read_file / list_dir / write_file / shell / python 通道

用户问「主 agent 和子 agent 能不能调这些工具」——查完发现三个真缺口，逐个补：

1. 文件读写工具**根本不存在**（49 个工具里没有一个 read/write）
   - 新增 tool/fs_tools.py：ReadFileTool / ListDirTool / WriteFileTool
   - 全部过 security.assert_allowed_path；读 ≤100KB、写 ≤200KB
   - 写文件**不自动创建父目录**，且父目录也要在白名单内（防 allowed/../../）
   - 注册进 ToolRegistry、agent_callable=True、能力矩阵档位 read/read/write_local
2. web_search / web_fetch 对主 Agent **不可见**
   - 旧语义 `is_available()` = 是否已配置搜索服务 → 未配置时工具根本不进 Kernel 工具面，
     主 agent 连"我能联网"都不知道
   - 改为 `is_available()` = 本体可用（无外部二进制依赖），新增 `is_configured()`；
     阶段 Agent 的可见性由 ToolRegistry.list_agent_callable() 用 is_configured 把关
   - 未配置时调用如实返回 DEPENDENCY_MISSING，不伪造空成功
3. shell / python 主 Agent **完全没有通道**
   - 它们被判定 dangerous 排除在工具面外（这是对的），但没有别的入口 → agent 实际不能跑命令
   - 新增 services/exec_capability.py：Kernel Step → supervisor.gateway（判定→授权→沙盒→审计）
   - pending_approval 语义：Step 保持 pending、任务转 paused、发 approval_request 事件；
     授权后 resume 继续（测试覆盖「等授权不算完成、不推进下一步」）
4. 子代理工具集同步扩充：+ write_file / web_search / web_fetch；worker_tools 委托注册表
   同一份实现（白名单语义只有一处），懒注册避免"工具未注册"
5. 顺手修两个真 bug：
   - security.is_within/assert_allowed_path 只收 Path，注册表传字符串必崩（AttributeError）
   - worker_tools 的 read/list 自己 open()，绕过了白名单——现改为委托注册表

测试：新增 29 条（fs 14 / web 可见性 6 / exec 9），并更新 2 条旧契约测试；
后端全量 3546 passed；能力矩阵 60 项、Kernel 可见 51 项
