# MG 动画预览还原度：人工比对规程（devplan T2.5，2026-11-02）

## 一、这件事解决什么

动画的中间表示是结构化 JSON（`mg/validator.py` 校验、`mg/generator.py` 产出），时间线上每个
`animation` clip 的 `metadata.mg_def` 就存着这份 spec。所以预览现在由**浏览器直接渲染**
（`src/features/preview/mgRenderer.ts`），不再显示"脉冲占位形 + 未渲染预览"。

但**浏览器渲染 ≠ 后端成片**。后端 `mg_renderer.py` 把同一份 spec 转成 HTML/CSS 交给
Hyperframes/Chrome 出帧，再进 FFmpeg；浏览器 canvas 渲染在以下方面必然有差异：

| 差异面 | 表现 | 归属 |
|---|---|---|
| 字体 | 缺字体时回退系统字体，字宽/行高变化 | 环境 |
| `filter` / `box_shadow` | canvas 只实现了部分滤镜 | 已知缺口 |
| 缓动 | 后端 `back-out/elastic-out/bounce` 映射到前端曲线，极值附近可能有偏移 | 已映射，需比对 |
| 元素类型 | `arc` 的起止角语义按 spec 假设（`start_deg/sweep_deg`） | 需比对 |
| 外部图片 | spec 里的外链 `src` **被拦截**（安全），显示为空 | 有意为之 |

因此：**预览是"看得懂、对得上大方向"的近似，最终成片以后端渲染为准**。预览头常驻
「近似预览」，当某片段确实存在差异时额外显示「N 处差异」角标（`useMgFidelityStore`）。

## 二、人工比对规程

准备 10 个模板（`clipwright/animation/mg/templates/` 里的内置模板即可，缺的用 animation
agent 现生成），每个采样 5 个时点：**0% / 25% / 50% / 75% / 100%**（按 clip 时长换算）。

对每个 (模板 × 时点)：

1. 在编辑器里把播放头拖到该时点，记录预览画面（截图或肉眼）；
2. 用同一份 `mg_def` 走 `POST /api/animation/mg/html` → 在 Chrome 里打开，拖到同一时点；
3. 记录差异等级：
   - `一致`：元素位置/大小/颜色/文字内容都对得上，肉眼无法区分；
   - `近似`：位置对、颜色对，但字体/阴影/滤镜有可见差别；
   - `不一致`：元素缺失、位置错、文字错、动画方向反了。

**验收标准**：10 × 5 = 50 个采样点里，`不一致` 必须为 0；`近似` 允许存在，但每个模板
要在本文件第二节末尾登记一行（模板名 / 差异面 / 是否已在角标里体现）。

## 四、什么时候该怀疑是 bug 而不是"近似"

出现下面任意一条，就不是字体差异，按缺陷查：

- 预览里**没有**这个动画元素，而 `mg_def.elements` 非空且类型在
  `text/shape/line/circle/ring/arc/bg/image` 之内；
- 元素位置整体偏移超过画布 5%（多半是 spec 的 `width/height` 与时间线分辨率不等比）；
- 文字内容与 `content` 不一致（占位符没替换）；
- 动画方向相反或静止（多半是 easing 映射错，或被 `keyframes` 只给 1 个而退化）。

## 五、不做的事

- **不把前端 canvas 帧拿去做成片**：导出链路仍走 `timeline → 后端渲染`，前端 canvas 只服务预览；
- **不执行模型生成的 HTML**：`metadata.mg_html` 在预览里一律不碰（只消费结构化 `mg_def`）；
  唯一可能用到 HTML 的场景是 sandbox iframe 回退，且不允许 same-origin。
