# 素材内容理解与自然语言剪辑落位 · 开发计划（2026-09-14）

> 目标一句话：**让 Agent 知道自己在剪什么，让用户说人话就能达到剪辑目的。**
> 本计划不含第三方非 OSI 代码，全部能力建立在已装依赖（torch/transformers/cv2/onnxruntime/easyocr/sentence_transformers）+ 本仓库既有件之上。

---

## 0. 可验收的目标定义

把"更懂内容"这种模糊目标拆成三条**可测**的目标：

| 编号 | 目标 | 验收方式 |
|------|------|----------|
| **G1** | Agent 知道素材里有什么 | 给一段真实素材，问 30 条具体问题（"有没有人在说话""特写在哪几秒""有没有黑场"），必须给出**区间 + 证据**，不是文件名 |
| **G2** | 用户用 NL 达成目的 | 50 条用户原话 → 结构化意图 → 落到具体区间 → 时间线真的变了，且能解释"为什么这么改" |
| **G3** | 不幻觉、不失控 | 所有 NL 落地都过 schema + 白名单 + dry-run；说不清就问，不猜 |

反面目标（明确不做）：不做"全片逐帧语义索引"（成本不可接受）、不做通用视频问答（没有明确用途）、不引入需要 GPU 常驻的重模型。

### 缺口（本次要补的）
1. **没有"镜头级内容记录"**：素材的视觉内容看完就丢，`MaterialAsset` 只有 title/tags/duration/metadata。
2. **没有素材内容检索**：`semantic_match` 仍是返回 0.5 的占位（`tool/vision.py:74`），rag/ 的检索栈没接素材。
3. **NL 只能改"已选中 clip 的数值字段"**：不能表达"只保留有人物的镜头"这类**内容条件**，也不能新增/删除/重排。
4. **方案不接地**：`ProductionPlan.scenes` 是自由文本，没有任何字段指向"具体哪段素材的哪几秒"。

### 依赖现状（本机实测）
`torch 2.12.0+cpu`、`transformers 5.13.0`、`cv2 4.13.0`、`numpy 2.4.6`、`onnxruntime 1.26.0`、`sentence_transformers 5.6.0`、`easyocr` 可用；HF 缓存已有 `vit-base-patch16-224`、`bge-small-zh-v1.5`、`bge-reranker-v2-m3`。
**缺失**：CLIP/SigLIP 权重、`librosa`/`soundfile`（音频事件若要做需自写 numpy 或新增依赖）、`ultralytics`（YOLO 若要做需新增）。

## 2. 架构：四层 + 三个契约

```
用户一句话
   │
   ▼  (C) 意图层       NL → EditIntent（结构化：ops + 引用 + 约束 + 目标）
   │                   ↕ 澄清回路（多候选/指代不明 → 反问 2-3 个选项）
   ▼  (C) 落位层       Intent → Resolver → 具体区间（ShotRef）+ 证据
   │                   ↖──────────────┐
   ▼  (D) 执行层       ops → Timeline patch（白名单字段）→ dry-run 校验
   │                                 │
   ▼  (D) 校验层       渲染前复核图 / QualityAgent / 失败回退          │
   │                                 │
   └── (B) 查询层  ◀───────┐         │
          内容问答/检索     │         │
   ┌── (A) 索引层 ──────────┘         │
      镜头切分 → 画面/语音/质量/镜头语言 → ShotRecord + embedding
```

### 契约 1：`ShotRef`（唯一寻址方式）
```
asset:{sha256[:12]}#s{shot_index}      # 稳定、可跨会话、可写进日志与 EDL
{asset_id, sha256, t0, t1, fps}        # 解析后的可用信息
```
**为什么用内容寻址而非文件路径**：素材会被移动/重命名/重复导入（asset_manager 本就按 sha256 去重），路径寻址会在会话之间失效。

### 契约 2：`EditIntent`（NL 的落点）
```jsonc
{
  "goal": "把这段素材剪成 60 秒的爆点集锦",
  "ops": [
    {"op": "keep",    "target": {"query": "有人物的镜头"}, "limit": null},
    {"op": "remove",  "target": {"kind": "black_frame"}},
    {"op": "reorder", "target": {"by": "excitement", "desc": true}},
    {"op": "set",     "target": {"ref": "clip:cl_07"}, "field": "speed", "value": 1.5}
  ],
  "constraints": {"total_duration_sec": 60, "platform": "vertical", "no_reuse": true},
  "unresolved": []      // 解析不了的引用必须写在这里 → 触发反问
}
```
- **op 词表固定**，未知 op 当场拒绝（不是让模型自由发挥）。
- `field` 复用 `_ADJUST_FIELDS` 的"类型 + 值域钳制"机制。
- `unresolved` 非空 → 必须反问，**禁止静默猜测**。

### 契约 3：`content_query` 的返回（Agent 读的东西）
```jsonc
{"summary": "42 个镜头：8 特写 / 3 含人物 / 语音提到'价格'2 次 / 1 段黑场",
 "hits": [{"ref": "asset:ab12…#s17", "t0": 12.4, "t1": 14.0,
           "why": "描述='人物特写，手部动作'；关键词命中'价格'", "score": 0.83}],
 "total": 42}
```
**摘要必须短**（几十行），这是 V6 短语打包（93.2% 压缩）已验证的原则：给 LLM 的是压缩结构，不是原始数据。

### 七个设计决策（先定死，避免中途摇摆）
1. **索引粒度 = 镜头**（语音短语对齐到镜头），不做帧级全索引。
2. **成本分层**：L0 切分（免费）→ L1 本地小模型（CPU：ViT/CLIP/启发式）→ L2 ASR（1× 时长）→ L3 多模态 LLM **只对"被选中的镜头"或按预算抽样**。
3. **缓存键** = `sha256 + index_version + model_fingerprint` → 增量、失效、复查天然成立。
4. **索引生成走后台任务 + SSE 进度**，可取消（`task_queue` / `trace` 既有约定）。
5. **NL 只落到真实字段**，字段词表与值域钳制集中在 `edit_intent.py` 一处（供 API/Agent/前端共用）。
6. **解析优先级**：显式选择/时间码 > 会话指代（最近候选集）> 检索（关键词 + 向量 + rerank）> 结构条件；平票 → 反问。
7. **每次落位都要留证据**（用了哪个 shot、为什么），写进 `project_memory` 与 trace，支撑"再改一次"。

## 5. 风险与对策

| 风险 | 对策 |
|------|------|
| 索引成本随素材时长线性爆炸 | 分层（L0/L1 优先）+ `budget.py` 上限 + L3 只对"用到的镜头" |
| 多模态描述不稳定/幻觉 | 结构化 JSON + 温度 0 + 证据字段 + 抽样人工复核；本地小模型优先 |
| 中文短查询语义检索效果差 | 复用 `bge-small-zh-v1.5` + `bge-reranker-v2-m3`；CLIP 只负责视觉召回，两者混合 |
| NL 说出系统不支持的操作 | op/field 词表 + 值域钳制 + dry-run；拒绝时给"我能做什么"的替代建议 |
| 时间线冲突（重叠/轨道非法） | dry-run 校验器 + 明确错误信息，绝不半应用 |
| 权重/许可风险 | 只用 HF 上的宽松许可权重（CLIP/SigLIP），不引入非 OSI 运行时；沿用现有许可审计流程 |
| 用户说不清 | 反问机制（给 2-3 个具体选项），把"猜"变成"确认" |

## 6. 拍板结果（2026-09-14，已确认）

| # | 事项 | 决定 | 落点 |
|---|------|------|------|
| 1 | 索引存储 | **本地内容寻址 + 可选 Mongo 镜像**（默认开镜像） | `<素材库>/content_index/<sha256>.json`；Mongo 集合 `content_index`（`sha256` / `text` 索引），`find_indexes()` 支持跨项目"我所有素材里找 X" |
| 2 | 素材帧送云端多模态 | **允许** | 设置项 `content_index_visual_llm`（默认关，开启后产生视觉 API 成本）；只对**候选镜头**调用，且走 `budget.py` 月度预算 |
| 3 | 下载 CLIP/SigLIP 权重 | **下载**（R9 使用） | HF 宽松许可权重；`vision_provider=transformers` 路径 |
| 4 | 评测素材来源 | **无真实素材** → 合成 + 公开素材建基准集 | `scripts/` 下用 ffmpeg 合成确定性素材做回归；语义检索基准另建 |

**R4 被实测逼出来的两个设计修正**（都不是"加个模型"能解决的）：
1. **自然语言 → 结构化条件的路由**：用户说的是"黑场在哪""哪些镜头有人脸""最长的镜头"，
   而这些词**根本不在镜头文本里**，纯关键词检索必然落空。于是加了 `route_query()`：
   "说法 → 条件/排序"的规则表（黑场→`is_black`、过曝→`min_overexposed`、掌声→`loud` 事件、
   最长→按时长排序…），命中后把该说法从查询词里剔除，避免污染关键词打分。
2. **排序/清单式问题必须直接给清单**：`"最长的那一个镜头"` 剔除口水词后没有内容词元，
   若仍走"打分→过滤"就会返回空。现在"清单式问法（哪些/列出/一共…）"或"无有效词元"
   一律走清单模式（条件+排序即答案），并保留"为什么"（`结构化条件命中`/`按 X 排序`）。

**R9 被实测暴露并修复的问题**：

- **transformers 5.x 的 API 变更**：`get_image_features()` / `get_text_features()` 返回的是
  `BaseModelOutputWithPooling` 而不是张量（旧版是张量），直接 `.norm()` 会抛
  `'BaseModelOutputWithPooling' object has no attribute 'norm'`——实测第一版**所有向量都是空的**，
  而检索"安静地"返回 0 命中（看起来像"没搜到"，其实是根本没算出来）。
  修：`_feature_tensor()` 兼容三种返回形态。
- **维度不匹配必须吵**：若索引里的向量来自另一个模型/版本，静默按 0 分处理会让人把
  "向量不可比"误判成"语义检索没命中"（两者排查方向完全不同）。修：告警 + 跳过 + 提示重建。
- **中文提示词里的虚词稀释信号**：第一版把未命中的中文原样拼进提示词，

| 跨素材检索 | 足球素材 + 城市素材两个索引里，按场景描述各取所需（3/3 场景都有引用） |
| 相关性排序 | 最相关的镜头排在引用列表首位（"球员射门进球" → `#s2` 射门得分，不是 `#s1` 带球） |
| 无相关画面 | **如实留白**：`material_refs=[]` + `material_gap` 说明"库里没有与「一碗牛肉面」相关的画面"——**不塞最接近的凑数** |
| 无索引 | 不产生任何假引用 + 说明"没有内容索引，规划书无法引用真实素材" |
| 结构化条件退化 | 描述含"全景"→ `route_query` 给出 `shot_size=wide` 硬条件，但 R2 对看不出景别的镜头写 `unknown`，硬过滤零命中 → **退化为文本匹配并标注 `material_match=degraded`** |
| 下游承接 | 场景引用 → `clip.metadata["material_refs"]`，"这一刀用了哪个镜头"可在时间线上回查 |

**R8 被实测暴露并修复的问题**：

- **硬过滤会把真素材全滤掉**：场景描述里天然出现"全景/特写"，`route_query` 把它变成
  `shot_size` 硬条件；而 R2 出于诚实把看不出景别的镜头写成 `unknown`——两者一叠加，
  "整库只有一个 wide" 这种真实情形下会报"没有可用素材"（实测第一版就是这样）。
  修：两遍检索 + 退化标注。**错误地说"没素材"比"匹配得不够准"代价大得多**。
- **得分为 0 的"命中"就是凑数**：退化到全库后如果连一个关键词都对不上，
  取前 3 个镜头等于凭空引用——下游会以为这一场有素材。修：**得分为 0 一律不算命中**，
  改报缺口。

**R8 的实现边界（如实）**：

- 验收用的索引与场景都是**构造数据**（合成素材、无真实模型），
  证明的是"接地链路与诚实性规则正确"，**不等于**真实素材上的匹配质量；
- 接地用的是**关键词/标签打分的规则检索**（零成本、可解释），**不含向量语义匹配**
  （视觉向量是 R9 的活）——所以"意思相近但用词不同"的场景目前匹配不到；
- **没有做"结构 → 时间线一致性"的强校验**：引用写进了 `clip.metadata` 供回查，
  但"时间线里实际用的素材是否覆盖了方案引用的素材"没有自动断言
  （EditAgent 的选段逻辑仍以素材检索结果为准，引用是**标注与意图**，不是强制约束）；
- `_ground_scenes` 在**复用时保留已有引用**（不覆盖人工指定），但"人工指定错了一个
  不存在的 ref"只会被 `validate_material_refs` 报出来，**不会自动纠正**。

**R7 的实测结论（一句话 → 成片，M2 达成）**：

| 项 | 结果 |
|----|------|
| 验收脚本 | `scripts/verify_intent_apply.py` **25/25 通过**（6 组案例） |
| "一句话→成片"①「删掉第2个片段」 | 5 片段 20s → 4 片段 16s；后续片段左移 4s 补齐；字幕轨一像素未动 |
| "一句话→成片"②「把所有片段速度调成1.5倍」 | 5 个视频片段速度全部 1.5，总时长不变 |
| "一句话→成片"③「剪到10秒」 | 20s → **精确 10.0s**（尾部整段删 2 个 + 末段裁到 2s） |
| dry-run 只读性 | 预览前后 `model_dump()` **逐字段一致**；`validate_patch` 内置自检（若被改动直接抛异常） |
| 全有或全无 | 补丁里任一条有硬错误 → **一条都不执行**，返回原时间线（不半途而废） |
| 门禁 | 有未答问题 / 补丁为空 / 幻觉 op → 一律 `blocked`，且**说明原因**（不许静默成功） |
| 补丁能力 | remove / keep / reorder / trim / set / add / transition / fit（8 种） |
| 收拢规则（ripple） | 只抽掉"被删/被裁的时长"，**保留幸存片段之间原有的留白**；且绝不制造新重叠 |

**R7 被实测暴露并修复的问题**（都是"只看代码看不出来、跑一遍就现形"的那类）：

- **R5 序号解析漏了中文的"名词尾巴"**：「删掉第 **2 个片段**」被当成内容检索词（`query="第2个片段"`），
  于是"删第 2 个"在真实时间线上零命中。修：序号正则接受 `第N个/段/条/画面+片段/镜头`，
  并顺带支持中文数字（「第三个片段」）。→ 这正是"3 条一句话→成片跑通"这条验收标准存在的意义。
- **R5 把"所有/全部"当成"选中的"**：「把**所有**片段速度调成 1.5 倍」在没选中的会话里直接落空
  （`set` 类操作原本硬编码 `target=selected`）。修：新增 `_scope_target()` 区分"显式全量"与"指代"。
- **收拢算法第一版把刻意留白也压掉了**：按"相邻间隙"计算会连被删片段占的时间一起当成留白。
  修：改成"累计位移"（只累计真正被抽掉的时长），并加了"原始就重叠时宁可少移"的保底。
- **裁剪后不收拢会留下无人解释的空洞**：删除不留洞、裁剪留洞，用户无从理解。修：两者共用同一条收拢规则。
- **"解析不出任何操作"曾静默成功**：「把这个视频变得更有感染力」返回 `applied=false` 但
  `blocked=false`，用户以为改了、回头看纹丝不动。修：判据改为"补丁为空且有未解析文本"→ 明确报错。
- **`desc` 默认值把"按时间重排"变成倒序播放**：`by=time` 现恒为升序（`desc` 只对统计排序有意义）。

**R7 的实现边界（如实）**：

- 验收素材是**合成时间线**（5 个 4 秒片段 + 1 条字幕），**没有真实素材、没有真实模型**；
  它证明的是"编译与执行链路正确"，**不等于**真实素材上剪得好不好；
- 6 组案例的指令与期望值都是**我自己写的**，不是真实用户语料；
- `add` 只支持"有真实素材（`asset_id`）"或纯文字（字幕/文本）两类：**没有素材就不许新增**，
  不编造路径（否则就是假数据）；
- `reorder` 按**内容统计**排序需要 R1–R3 的内容索引；索引缺失时按时间排序并**如实告警**
  有多少片段"无依据可排"（不拿默认值凑数）；
- 总时长约束（`剪到 N 秒`）的实现是**从尾部裁**，不改变片段顺序与内容选择——
  "挑更好的留下"属于内容选择（R4/R6）的范畴；
- 前端确认卡"确认执行"现在走 `/intent/apply`（执行用户看到的那份补丁），
  但**未做真实浏览器验收**（客户端测试是 jsdom + mock，视觉与交互手感未验）；
- 冲突检测只覆盖**同轨道时间重叠**（告警）与结构不变量（错误）；
  跨轨道的语义冲突（如字幕与画面内容不符）不在本轮范围。

**R6 的实测结论（引用落位 + 确认门禁）**：

| 项 | 结果 |
|----|------|
| 引用落位（索引命中片段 → 时间线 clip） | 按 `asset:{sha}#s{n}` 回连 clip，命中即给出精确 clip_id（脚本 17 例全过） |
| 会话指代（"刚才那几段"/"上面找到的"） | `SessionRefState` 保留最近 5 个短名单，指代走短名单并集；无短名单时**不猜**，转反问 |
| 歧义处理 | 匹配为空或候选过多（>12）时**100% 反问并给出可选项**，不自行挑一个执行 |
| 序号语义 | `第2个` 解释为**时间线位置**（会话相对位置会随上一轮编辑漂移，用户看到的是时间线） |
| 预览只读性 | `/intent` 走 `preview_intent()`——只读时间线与索引，返回 `preview/questions/problems`，**不写任何状态**；脚本有断言 |
| 降级标注 | 命中片段若索引信息不完整，`degraded` 只标在**实际匹配到的片段**上，不扩散到整条时间线 |
| 前端门禁 | 有未答问题 / `problems` 含 error / `blocked` 三种情况都**禁用确认按钮**（客户端 15 条测试覆盖，含"`/intent` 挂了静默降级回旧路径"） |

**R6 被实测暴露的问题（已修）**：
- 序号最初按"会话内第 N 个"解释，与用户心智（时间线第 N 个）不一致 → 改为时间线位置；
- 指代词最初被当作**文本检索词**送进 `route_query`（"这段"会匹配到含"这"字幕的片段）→ 改为映射到 `selected`，
  并加 `is_deictic_phrase()` 在 R5 层拦截；
- `degraded` 最初只要时间线里存在无索引片段就置位 → 收敛到"仅匹配到的片段"。

**R6 的实现边界（如实）**：
- 反问策略是**阈值 + 规则**（空命中 / >12 候选 / 指代无短名单），不是概率化的澄清决策；
- 会话短名单只活在**进程内存**里（`_MAX_SHORTLISTS=5`），重启即失忆，也未按 session 做跨进程共享；
- 「歧义 100% 反问」是在**自写夹具**上的结果，且反向也有代价：过于保守时会多问一句
  （基准里这被记为"可接受的啰嗦"，但真实体验好坏未做用户测试）；
- 前端确认卡只做**渲染 + 门禁**，点"确认执行"仍走既有的 `/edit` 通路；
  真正由 ops 驱动的时间线补丁执行是 R7 的活。

**R5 的实现边界（如实）**：
- 基准夹具是**我自己写的 50 条**，不是真实用户语料；因此 100% 说明"常见说法已覆盖 + 无回归"，
  **不等于**真实用户输入上的正确率；
- LLM 解析路径只有**打桩测试**（`structured_output` 返回构造的 JSON），没有对接真实模型跑过；
- 规则解析器对长尾说法**故意不猜**：解析不出就进 `unresolved`（由 R6 反问），
  基准里 4 条长尾正是按"必须进 unresolved"判定的；
- 中文数字支持常规写法（〇-十/百/千），不支持"两百五十六"这类省略式与财务大写。

**R2 的实现边界（如实）**：
- **合成素材上的标签不可信**：实测纯色/纹理合成帧上，CLIP 只能给出"屏幕录制/字幕板/空镜"这类
  弱相关标签，本地 ImageNet 分类器甚至给出"revolver（左轮手枪）"这种明显无关的结果
  （典型的分布外失败）。真实拍摄素材的表现**尚未验证**——这是本轮最需要后续补的验证。
- 镜头语言只做了"景别 + 是否有人脸"，且依赖 OpenCV 自带级联/HOG（弱检测器）；
  运镜（推拉摇移）**没有**做，`camera_motion` 仍是帧间差启发式。
- 云端多模态通道已接通但**默认关闭**，且本次验收**没有真实调用过**云端（只做了打桩测试）。
- `INDEX_VERSION` 升到 2（ShotStats 增加质量字段），旧索引会自动重建（不是迁移）。
