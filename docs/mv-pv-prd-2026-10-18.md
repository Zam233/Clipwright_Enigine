## 0. 一页结论

| 问题 | 答案 |
|---|---|
| 类型系统要改什么 | 类型插件从「只给数字」升级为「给规范」：**提示词定义类型同一性**，参数只在类型内调剂量。10 个槽位（身份层 `genre/anti_patterns/lexicon` + 阶段层 7 个）+ `param_rules` + `signature_traits` + `declares` |
| MV 能力要补什么 | ① 场景脚本 `renderFrame(t)` 合成类型；② 三类画面构件库（界面/版画/代码）；③ 版画印刷库 9 原语；④ 歌词卡点（grid/snap/cues）；⑤ 三道闸（确定性/拍点/闪光）；⑥ `lyric_mv` 类型的规范；⑦ **C13 素材识别与落位**（素材型 MV 的前提）；⑧ **创作页改造**（去驱动模式二选一 + 提示词区 + ChatForge 抽屉） |
| 最难的一块有没有 | **有**：`hf_timeline.py` 已实现 HyperFrames 确定性 seek（`window.__timelines[compId].seek(t)`），任意 HTML 全帧合成也能渲（`hyperframes_renderer.py:482-524`）。缺的是作者层与效果库，不是引擎 |
| **能不能做「一切」MV/PV** | **能做 18/20 类**（把"**素材识别 + 落位**"算进能力后）：① 自给自足（纯程序化）9 类；② **素材由用户提供、系统负责识别→打标→检索→落位→卡点→合成** 9 类（含手绘、2D 骨骼、3D CG、真人实拍、混剪、一图流、实拍合成、摄影主导、多机位）；③ 真不能的只剩 2 类：交互式 MV（交付物是线性视频）、故意频闪（安全红线）（§III.4） |
| 判定标准（一句话） | 「凡能写成**时间的纯函数 + 素材/资产输入**的片子，本系统理论上就能做；**素材可以是外部来的，只要能被识别并放进指定位置**」——系统的边界不是"素材从哪来"，而是"能不能识别与落位" |
| 素材类靠什么成立 | 已有底座：`services/content_index.py`（44KB 镜头级索引）、`content_vision.py`、`content_semantic.py`、`content_query.py`、`scene_grounding.py`（13KB，NL → 落位）、`indexer.py`。**要补的**是 C13：把"识别→打标→检索→按乐句/关键词/拍点落位"接到 MV 工序上，并加素材台账（来源/授权/可用区间） |
| 前端创作页要改什么 | 去掉「配音驱动 / 视觉驱动」二选一（`HomePage.tsx:893/901`）；新增「提示词」区；**右侧新增对话按钮 → 打开新的 ChatForge 会话**，用于打磨视频提示词并回填（§II.12） |
| 需求 agent 要改什么 | 从"按写死的 9 字段填空"改为**动态生成整体规划**：先出结构化 `PlanDocument`（段落目的 / 卡点策略 / 画面类型分配 / 素材策略 / 风险 / 验收指标），由类型 `plan_schema` 决定维度；**创意简报与规划书两份文档都保留**，但规划书是**规划的上游**、且由结构化对象**确定性渲染**成 Markdown（不再让 LLM 自由写）。详见 §II.13 |
| 若"无中生有"也要 | 另立两条可选能力线：G1 图像生成（造型）、G2 3D/WebGL（体积），≈23–37 人日；**不做也能覆盖 18 类**（因为这 18 类不要求系统自己"画"或"拍"） |
| 分期 | Part I：P0（4）→ P1（5）→ P2（3）≈**12 人日**；Part II：M0 场景脚本 + POC（5）→ M1 版画库（4）→ M2 歌词卡点（3）→ M3 腐坏特效（3）→ M4 编排交付（4）→ M5 4K（3）→ **M6 素材识别落位（4–6）→ M7 创作页（3）→ M8 需求 agent 动态规划（5–7）** ≈**34–38 人日**。均不含内容工作（示例工程包、版画设计 ≈6 人日） |
| 最大风险 | ① 场景脚本是任意 JS（执行安全）；② 逐帧浏览器渲染成本；③ 闪光安全的合规责任；④ 效果库做成"只有名字没有实现"（假功能）；⑤ 素材落位变成"随机贴图"（必须给依据 + 报 `material_gap`） |

# Part I 类型插件提示词化（通用机制）

## I.1 现状与问题（代码证据）

### I.1.1 类型插件目前只能表达数字

`clipwright/category/` 的 4 个内置类型 + 动态类型，对外能力实质只有两类：量化参数（`shot_params / transition_weights / cut_on_beat`）与几个"半个提示词"钩子。参数进管线的路径是确定的：

```
pipeline_v2._init()
  translated = plugin.translate_persona(persona.parameter)
  extra_params = {**translated, **request.extra_params}      # pipeline_v2.py:1518
     ↓
edit_agent: shot_params = extra_params["shot_params"]         # edit_agent.py:280
  base_shot_ms = shot_params.get("base_shot_ms", 5000)        # edit_agent.py:287
  # LLM 剪辑档案结果再按 min/max 钳制                          # edit_agent.py:738-745
```

**今天"类型"能进系统的地方，全部是数字。**

### I.1.2 类型规范其实存在，但散落在 Agent 里（5 处硬编码）

| 位置 | 内容 | 本质 | 应属于 |
|---|---|---|---|
| `structure_agent.py:722` | `_DATA_CHART_CATEGORIES` + `_DATA_CHART_KEYWORDS` | 「知识/评测类必须有图表」 | 类型插件 |
| `structure_agent.py:824` | `_OUTRO_ANIMATION_CATEGORIES` | 「这几类必须有片尾动画」 | 类型插件 |
| `structure_agent.py:853` | `_OPENING_ANIMATION_ALLOWED_PLUGIN_IDS` | 「这几类开场允许动画」 | 类型插件 |
| `material_agent.py:156` | `_CATEGORY_SEARCH_HINTS` | **一段自然语言选片规范**，被硬编码在 Agent 里 | 类型插件 |
| `quality_agent.py:72` | `_SEMANTIC_QA_DEFAULT_ON` | 「这几类默认开语义质检」 | 类型插件 |

后果：第三方类型（`plugins/{news,gaming,tutorial,shortform}_category`）永远拿不到这 5 条待遇。

### I.1.3 已有 3 个 prompt 钩子：无优先级、无治理、有格式 bug

| 钩子 | 定义 | 消费点 | 问题 |
|---|---|---|---|
| `get_structure_template()` | `base.py:58` | `structure_agent.py:747-755` | 契约写 `-> str`，4 个外部插件全返回 `list[dict]`；消费端 `str(...)` → 把 `[{'role': 'headline', ...}]` 原样 repr 进 prompt |
| `get_annotation_templates()` | `base.py:67` | `structure_agent.py:756-764` | 同上（`list[dict]` vs `list[str]`） |
| `get_mg_style_guidance()` | `base.py:84` | `animation_agent.py:143-165` | 仅注入 MG 生成，其余阶段无份 |

共同问题：无优先级（三条文本与 Persona prompt、插件 prompt 平铺）、无长度治理、无留痕。

### I.1.4 自定义类型完全无法表达提示词，且加字段会被静默吞掉

- `api/type_maker.py:TypeDefinition` 只有 `shot_params / persona_mapping / post_process / tags`，**没有 prompts**；
- `DynamicCategoryPlugin`（`category/dynamic.py`）同样，且 `get_structure_template` 等钩子**未实现** → 自定义类型零规范注入；
- `TypeDefinition` 未声明 `prompts` 且未设 `extra` → 加字段后 `PUT` 会**静默丢弃**（必须先修）。

### I.1.5 根本问题：参数在原理上表达不了"类型"

| 问题 | 参数能否回答 | 例（同一选题「手机续航」） |
|---|---|---|
| 多快？多长？多密？占比？ | **能** | `min_shot_ms / transition_weights / 段落占比` |
| 这是什么片子？什么不许出现？像不像？ | **不能** | 鬼畜靠"熟梗音画错位 + 机械重复 + 踩点"；动画区靠"二维美术 + 分镜演出"；知识区靠"论证链条 + 图表"。三者镜头时长区间**可以完全相同** |

今天系统里所有"类型感"的来源，其实都是那 5 处硬编码 + 3 个钩子里**偶然写下的自然语言**——**类型靠提示词起作用，只是这些提示词写错了位置、且没有优先级。**

## I.2 目标 / 非目标

| 编号 | 目标 | 可验证形态 |
|---|---|---|
| G1 | 类型插件能携带分阶段提示词 | 10 槽位（身份层 3 + 阶段层 7），`genre` 必填 |
| G2 | 提示词**定义**类型、优先于参数 | 提示词先行定域，`param_rules` 在域内收紧；参数不得把一种类型变成另一种 |
| G3 | 类型规范从 Agent 搬回类型插件 | 5 处硬编码 → `declares`，本期清除 |
| G4 | 自定义类型（YAML/前端）能用 | `prompts` 进 YAML/API/前端，PUT 不丢 |
| G5 | 规范可审计、可复现 | `prompt_resolution` 进 trace；同输入两次裁决逐字节一致 |
| G6 | 提示词不成为越权通道 | 保存前越权检测 + 注入位置固定 + L0 不可覆盖 |

## I.3 优先级与裁决

### I.3.1 两个职责通道

| 通道 | 回答的问题 | 只能由谁承载 | 可量化性 |
|---|---|---|---|
| **同一性通道** | 这是**什么**片子？ | **只能提示词**（`genre / anti_patterns / lexicon`） | 不可直接量化；用 `signature_traits` 做可测代理 |
| **剂量通道** | 该**多快/多密/多长**？ | 参数为主，提示词也可发规则 | 可量化、可钳制、可校验 |

> **参数属于剂量通道，无法表达同一性。** 鬼畜/动画区/知识区的参数可以完全一致，但必须是三种片子。一旦参数配置实质改变类型 → 判 `type_deformation`，不许"照参数执行"。

### I.3.2 六层优先级（L0 最高）

| 层 | 来源 | 权限 | 可否被下层覆盖 |
|---|---|---|---|
| **L0 平台硬底线** | 系统内置（安全/合规/平台红线/法务/未成年人保护） | 只读 | **不可**（类型只能加严） |
| **L1 用户本次显式输入** | `extra_params`、手改时间线、滑块、人工确认简报 | 可改剂量、**不可改同一性** | 可被 L0 否 |
| **L2 类型插件提示词** | 身份层 + 阶段层 + `param_rules` + `signature_traits` | **定义类型与允许域** | 仅 L0 可否定 |
| **L3 类型插件量化参数** | `shot_params / 密度档 / transition_weights / declares` | 在 L2 域内取剂量 | **L2 定义域，L3 只能向内取值** |
| **L4 Persona 参数层** | `rhythm / visual / audio / constraints` | 域内微调 | L1/L2/L3 可覆盖 |
| **L5 系统默认** | 代码兜底（如 5000ms） | 兜底 | 全部可覆盖 |

> 现状 L1 > L3 > L4 > L5 已成立；本次插入 L2，且**不是"事后钳制"而是"先定域"**。

| C3 | L2 文本 vs L3 数字 | **L2 赢**，L3 值不生效 | `overridden_by: prompt` |
| C4 | L2 vs L4 | L2 赢 | 同上 |
| C5 | L1 vs L4 | L1 赢（现状） | 无 |
| C6 | L0 vs 任何 | L0 赢，标 `blocked_by_platform`，不成片 | 红条 + 原因 |
| C7 | 声明 `required_animation_markers` 未落位 | 确定性兜底注入 + issue | 质检报告 |

| **C10** | 数字全合规但同一性校验不过 | 标 `type_mismatch` + 一次定向重做；仍不符 → 带「类型不符」标记交付 | 黄条 + 质检一节 |

### I.3.4 阈值不行，就给"可测代理"：`signature_traits`

| 类型 | 提示词里的同一性描述（不可量化） | 可测代理指标 |
|---|---|---|
| 鬼畜 | 熟梗音画错位、机械重复、踩点驱动 | `repeat_shot_ratio ≥ 0.2`、`av_mismatch_count ≥ 3`、`beat_align_ratio ≥ 0.6`、`avg_shot_ms ≤ 1500` |
| 动画区 | 二次元美术调性、分镜演出 | `illustration_clip_ratio ≥ 0.7`、`camera_move_count ≥ 6`、`keyframe_density` |
| 知识区 | 论证链条完整、图表支撑 | `chart_count ≥ 1`、`argument_segment_count ≥ 3`、`avg_shot_ms ≥ 2000` |
| **歌词 MV**（Part II） | 整片是一场对话；版画是内心；卡点驱动 | `cut_on_beat_ratio ≥ 0.95`、`flash_violations = 0`、`determinism_equal = true`（详见 II.3 C10） |

规则：指标由管线在结构/剪辑阶段采集，进 `prompt_resolution.traits`；`mode = require_ge | require_le | require_between`，默认只记录，每类型 ≤3 条可设 `strict`；**指标与 `genre` 文本矛盾 → 拒绝保存**。

### I.3.4b 三类型最小对照（证明参数不够、提示词必需）

同一选题「手机续航实测」，三套类型定义：

| | 知识区 `knowledge_longform` | 鬼畜 `kichiku` | 动画区 `anime` |
|---|---|---|---|
| `genre` 一句话 | 论证链条驱动、图表支撑、讲清原理 | 熟梗音画错位驱动、机械重复与踩点制造喜感 | 二维美术与角色演出驱动，像一段动画短片 |
| `anti_patterns` | 不是段子；不许无依据类比 | 不是讲解片：禁止完整论证与结论段 | 不是真人拼贴：禁止实拍素材当主画面 |
| `signature_traits` | `argument_segments ≥ 3`、`chart_count ≥ 1`、`avg_shot_ms ≥ 2000` | `repeat_shot_ratio ≥ 0.2`、`av_mismatch_count ≥ 3`、`beat_align_ratio ≥ 0.6`、`avg_shot_ms ≤ 1500` | `illustration_clip_ratio ≥ 0.7`、`camera_move_count ≥ 6`、`keyframe_density ≥ 4/秒` |
| `shot_params` | min 2000 / max 15000 / 硬切 0.8 | min 200 / max 1500 / 硬切 1.0 | min 600 / max 4000 / 硬切 0.6 |

**为什么参数区分不了**：把鬼畜的 `max` 改到 5000，参数层面就"像知识区"了——而它仍然是鬼畜（重复、错位、踩点一个不少）。动画区的镜头时长可以落在知识区区间里，片子依然一眼是动画。**参数描述剂量，提示词描述同一性。**

### I.3.5 一句话规则

> **提示词说"这是什么片子"，参数说"这个片子多快多密"；参数只能在提示词划定的类型之内取值，不能反过来定义类型。冲突不许静默；要改类型，就换类型。**

### I.3.6 纪律：「不许有悬空数字」

提示词文本里凡涉及可量化边界（`\d+\s*(ms|毫秒|秒|s|%|倍)`），**必须**在 `param_rules` 声明；否则校验器无法执行、等于没写。不可执行表述可标 `〔不可执行〕` 并写理由，进 `waivers`。同一纪律适用于 `signature_traits`（文本说"缓慢长镜"、指标却要 `avg_shot_ms ≤ 800` → 拒存）。

## I.4 功能需求

### F1 提示词槽位（10 个）

**身份层（同一性，参数无法替代）**

| 槽位 | 注入到 | 作用 | 要求 |
|---|---|---|---|
| `genre` | 所有阶段 system prompt 最前的「类型同一性」段 | 叙事逻辑、镜头语言、声音质感、情绪曲线 | **必填**，写成"可判别"描述 |
| `anti_patterns` | 紧随其后「本类型禁止/易混淆」小节 | 本类型**不是**什么 | 至少 1 条（防串味的关键） |
| `lexicon` | `subtitle/edit/quality` 共用 | 术语与黑话口径 | 可选 |

**阶段层**：`structure / material / edit / animation / audio / subtitle / quality`（各注入对应 Agent；`animation` 收编 `get_mg_style_guidance`，`material` 收编 `_CATEGORY_SEARCH_HINTS`，`quality` 收编 `semantic_qa_default`）。

槽位结构：`{text, priority(0-100), max_chars?}`；空槽位不注入（零行为变化）。`global` 视为 `genre` 的别名（简化入口）。

### F2 裁决引擎 `PromptAuthority`

裁决顺序（关键）：① 确认同一性（`genre` 非空）→ ② 用 L2 定允许域 → ③ 域内合并 L1/L3/L4/L5 取剂量 → ④ 域内无合法值 → `type_deformation` 中止。

输出三产物：`resolved_params`（带 `value/source_layer/source_id/overridden/clamped_by`）、`resolved_prompts`（带 `text/sources[]/truncated`）、`traits`（指标可达性预判）。禁止 Agent 继续直接读 `extra_params["shot_params"]` 并自行兜底 5000。

### F3 `param_rules`

```yaml
param_rules:
  - key: min_shot_ms            # 支持点号路径
    mode: floor                  # floor|ceiling|exact|forbid|require
    value: 1200
    reason: 评测需要看清参数页，禁止 1 秒内快切
    enforce: strict              # strict 覆盖用户显式值(C1)；soft 只记录(C2)
```

floor/ceiling 后置生效（后者胜出 = 提示词赢）；同 key 取更严；floor>ceiling 出现不可能区间 → 保存报错。

### F4 旧钩子归一

`BaseCategoryPlugin.get_prompt_bundle()` 默认由三个旧钩子合成 → 第三方插件一行不改也有提示词；返回类型归一 `str | list[str] | list[dict]`（`list[dict]` 渲染成 `"- {role}（权重 {weight}）：{desc}"`）。

### F5 硬编码迁出（`declares`）

declares:
  required_animation_markers: [data_chart]   # 原 _DATA_CHART_CATEGORIES
  outro_animation: true                      # 原 _OUTRO_ANIMATION_CATEGORIES
  opening_animation: false                   # 原 _OPENING_ANIMATION_ALLOWED_PLUGIN_IDS
  semantic_qa_default: true                  # 原 _SEMANTIC_QA_DEFAULT_ON
  search_hint: 数码评测类：优先搜索产品特写…  # 原 _CATEGORY_SEARCH_HINTS

  requires: [scene_script, inks, flash_check]  # 能力依赖（Part II）

### F6 自定义类型带提示词

`TypeDefinition` 增加 `prompts / param_rules / signature_traits / declares / waivers`；`model_config = {"extra": "forbid"}`（未知字段 400，修 A3）；`DynamicCategoryPlugin.get_prompt_bundle()` 读 YAML；保存校验：槽位键名、`max_chars`、规则冲突、悬空数字、指标矛盾、越权模式。

### F7 治理

| 项 | 规则 |
|---|---|
| 单类型总量 | **≤4000 字符（已拍板）**，超限保存报错；运行期单槽位超 `max_chars` 按句截断并告警 |

### F12 类型同一性校验（三级）

| 级 | 做法 | 阻断 |
|---|---|---|
| **L1 可测代理** | 确定性计算 `signature_traits` | `strict` 不达标 → 一次定向重做 |
| **L2 LLM 裁判** | `genre`+`anti_patterns` 转检查项，**必须引用时间线具体镜头/秒数作证据**；无证据不得判不符 | `score < 70` 或命中 `anti_patterns` → `type_mismatch` |
| **L3 反例检验** | `genre` 与 `declares.neighbors` 的描述并列问"更像哪个" | 选中相邻类型 → `type_mismatch` |

**V17 落地（2026-10-22）**：L2/L3 已有真实现——`services/genre_judge.py`（真 LLM 裁判 + 结构化 JSON + 时间线摘要分段统计 `video_clip_count/caption_clip_count`），`acheck_conformance` 提供 async 通道，`/api/type-maker/{id}/genre-check` 与质检 Agent 都走它。开关 = 单次请求 `enable_genre_judge` 或服务端 `CLIPWRIGHT_GENRE_JUDGE_ENABLED`（都默认关）。真机取证（`scripts/e2e_genre_judge_v17.py`）里**最关键的一格**是：某条时间线 L1 两项全过，但字幕内容是口播稿 → 裁判 `mismatch`（conf 0.96）并引用 `caption_clip_count` 与字幕原文；MV 形态则 `passed`（0.90）。

### F13 类型变形保护与类型切换

| 情形 | 判定 | 出路 |
|---|---|---|
| 参数在允许域内 | 通过 / C1 黄条 | 正常出片 |
| 组合使指标结构性不可满足 | `type_deformation`（C9） | ① 回落到合法域 ② **切换类型**重新出片 |
| 请求里换 `category_plugin_id` | `type_switch`（正常） | 按新类型出片，旧规范失效 |

`type_deformation` **不允许豁免**（豁免只能豁免剂量级规则）。

### F14 类型声明规划维度（`plan_schema`）

规划不能是"所有类型同一张表"。类型插件在 `declares` 里声明本类型的**规划维度**，需求 agent 据此动态生成（详见 §II.13）：

```yaml
declares:
  plan_schema:
    required: [sections, screen_kinds, material_strategy]   # 缺则拒绝确认
    optional: [beats, risks, acceptance, continuity]         # 有则必填内容
    custom_allowed: true                                     # 允许 custom_sections（须带 reason）
```

规则：① `required` 维度缺失或为空 → `plan_ready → plan_confirmed` 转换被拒；② `custom_allowed=false` 时出现未知维度 → 拒；③ 未声明 `plan_schema` 的类型 → 用系统默认维度（`sections + material_strategy`），行为与今天一致（零破坏）。

**验收**：同一首歌分别用 `lyric_mv`（要求 `beats`）与 `knowledge_longform`（不要求 `beats`）出规划，前者缺 `beats` 被拒、后者不被要求。

export interface ResolveResult {

## I.6 决策权矩阵（谁提案、谁裁决）

> 这条是 v1.0 新增：**技术与艺术选择不写在文档里当硬规则，而是写清"谁提案、谁裁决"**。背景透明度就是第一个案例。

| 事项 | 提案方 | 裁决方 | 依据与冲突处理 |
|---|---|---|---|
| 片段是否**整帧不透明**（全帧合成 vs 叠加层） | **动画 agent**（按镜头语义：该镜是否"自成一体"的画面） | **主 agent 最终裁决** | 透明 = 叠加层路径；不透明 = 全帧合成路径。同段混用会产生接缝，故必须跨镜头统一裁决；不一致时以主 agent 结论为准并记 `composition_mode` 事件 |
| 类型 `genre / anti_patterns / signature_traits` | 类型作者 / 动画 agent | 主 agent（保存前校验 + 冲突裁决） | §I.3 |
| `param_rules` 值与 strict/soft | 类型作者 | 主 agent（`resolve` 干跑） | §I.4 F3 |
| 逐词时间（measured vs init） | 卡点子 agent | 主 agent（可降级 init） | Part II |
| 是否开启 LLM 同一性裁判 | 系统默认关（D7） | 用户/主 agent 按需开 | §I.4 F12 |
| 4K 导出范围 | 交付子 agent 提议 | 主 agent | Part II D3 |

**背景透明度的判定要点（供动画 agent 使用，不是硬规则）**：

| 镜头语义 | 建议 | 理由 |
|---|---|---|
| 该镜是"一段独立画面"（版画、代码、全屏界面特写） | 不透明 | 无下层需求，透明反而多一次合成 |
| 该镜要压在实拍/图片素材之上 | 透明 | 需要下层可见 |
| 该镜是"界面浮在版画纸上" | 不透明底 + 内部图层透明 | 一段合成内部解决，不跨段混路径 |
| 同段前后切换路径 | 避免 | 接缝与色差，主 agent 应要求统一 |

**人工验收（Part I，无法自动化）**

1. **同一性对比**：同一选题用「旧（仅参数）vs 新（参数+规范）」各出 3 条，请 2-3 人盲评"哪个更像该类型的片子"，新方案须 ≥2/3 占优——否则是规范写得不对，不是机制不对。
2. **跨类型对比（最重要）**：同一选题按鬼畜/动画区/知识区出片，三条混在一起让人判断"哪条是哪个类型"，**全判对才算通过**。
3. **三级冲突体感**：让人手动改鬼畜的最短镜头，验证"品味级放行（2.4s→2.0s）"与"同一性级拦截（把踩点密度改没）"两种表现都符合 §I.7 D1。

## I.10 风险与不做（Part I）

风险：规范写了但裁决没接管（假功能，用 V2/V5 直接验）；自定义提示词成越权通道（F9/V11）；上下文被挤爆（F7）；第三方行为突变（旧钩子适配器 + `declares` 兜底一周期）；裁判误判（必须给证据）；代理指标被"刷"（每类型 ≤5 条、核心 ≤3 条 strict）。

不做：类型继承/组合；提示词自动生成；运行时热替换；改 Persona 四层；让 LLM 自由裁决类型（必须先过 L1）；画面级审美评分。

## II.3 能力清单（C1–C13）

### C1 场景脚本片段（现状：**半**）

一个片段 = 纯函数合成：输入 `t`，输出一帧；全采样由渲染器负责；禁跨帧状态/定时器/随机（走 `prng(t)`）。

- **已有**：`hf_timeline.py:1-100` 已实现 seek 契约（`window.__timelines[compId].seek(t)`），WAAPI `pause()` 后按 `t` 设 `currentTime`；注释引用上游 `determinism-rules.md`，实测 180 帧 108.2s→18.0s。
- **缺**：只有 CSS keyframes 一条路，作者无法"一个函数画一切"。
- **要加**：`scene_script` 合成类型（`compositions/<name>/{index.html,scene.js}`，导出 `renderFrame(t, ctx)`；`seek(t)` 调它；`preload` 允许一次像素读取，渲染期禁 `getImageData`）。

### C2 三种画面构件（引擎 **有** / 构件库 **无**）

**先分清"能不能渲"和"写没写"**：模拟一个应用界面就是渲染一页 HTML，这正是 HyperFrames 的本职——`hyperframes_renderer.py:482-524` 造全帧页面（`<div id="root" data-composition-id="main" data-duration>`），`render_mg_html_to_mov()` 可渲任意 HTML。**聊天界面、版画、代码终端对渲染器没有区别。**

| 构件 | 内容 | 引擎 | 构件库 |
|---|---|---|---|
| 聊天界面 | 标题栏、线程、气泡、输入框、游标、设置抽屉、状态灯 | 能渲 | **无** |
| 版画 | 纸底、三墨图形、大字、剪影、代码符号画 | 能渲 | **无** |
| 代码画面 | 行号高亮清单、滚动终端、逐位计数 | 能渲 | **无** |

要加 `components/chat|plate|console/`（HTML+CSS+JS，零网络、字体本地），以及三条**实现纪律**（不是审美规则）：

1. **背景透明/不透明由动画 agent 按镜头语义决定，主 agent 最终裁决**（§I.6 决策权矩阵）。文档不硬性规定；但同一段内应统一，跨段切换要主 agent 明确记录 `composition_mode`。
2. 界面里的"活物"（打字光标、消息落下、状态灯、抽屉滑出）**全部由 `t` 推导**，不用 CSS `animation` 隐式时间轴（会绕过 `seek`），不用 `setTimeout`。
3. 落点数据化：`renderChat(t, state)` 的 `state` 来自 `cues.json` + `chat_script.json`——"第几条消息在第几拍落下"是数据，不是写死在组件里。

**这是 v1.1 新增、也是"能做一切"的关键一条**：真实拍摄、物理材质、人手技法、真人表演**不需要我们去生成**，只需要**认识它、并把它放到指定位置**。

**规则**（必须写进实现，否则"识别落位"会变成随机贴图）：

1. 落位必须有**依据**：每个 clip 记录 `matched_by`（关键词 / 语义相似度 / 标签 / 显式指定）与分数，进 `report.json`；
2. 没有合适素材时**不许**用无关素材凑数——报 `material_gap`，并在交付里列缺口（参考样本的"素材缺口清单"同理）；
3. 落位必须服从 C7 的拍点：切点先落拍网格，再在拍内选 in 点；
4. 授权不明的素材**不进成片**（可进"待确认"清单）。

**验收**：给 10 个已拍摄素材 + 一段 30 秒歌，系统能出"每句歌词配到语义相符的镜头"的成片，人工抽检 10 个落位 ≥8 个认可。

## II.4 主 agent / 子 agent 编排

### II.4.1 工序

```
① 读入：wav + 歌词 + Persona + 用户意图
② 卡点先行：build_grid → build_cues（cues.json 是唯一时间真相）
③ 骨架：分镜表（每镜绑定画面类型与进入拍点）
④ 并行分派（子 agent 产物分区，互不写同一文件）
⑤ 汇总装配 → 1080p 预览
⑥ 三道闸：确定性 → 拍点 → 闪光
⑦ 交付出包
```

### II.4.2 子 agent 角色（7 个）

| 角色 | 产物 | 验收口径 | 失败降级 |
|---|---|---|---|
| 卡点分析师 | `cues.json` | 起音偏差 ≤42ms；每项标 measured/init | 用歌词行级时间 + 半拍吸附，标 init |
| 界面构件师 | `components/chat/*` + `chat_script.json` | 消息落点卡拍（数据驱动）；光标/状态灯可由 `t` 复算 | 静态界面 + 单条消息高亮 |
| 版画美术师 | `assets/plates/*` + 单帧 | 不看字能认出；三墨可分离；边缘无脏点 | 后备顺序（字符版画→剪纸→排版）并列入交付 |
| 场景程序员 | `compositions/<seg>/scene.js` | 单帧自查 + 确定性 lint | 换模板/简化构图，不许留空镜 |
| 字体动画师 | `components/lyrics/*` | 歌词演唱时长内可读；关键词位置锁定 | 字幕带 + 关键词静态大字 |
| 腐坏特效师 | `components/decay/*` | 降帧率、撕裂 ≥6 帧、错位量可配 | 关闭该效果（默认关闭） |
| 闪光审查 | `report.json` flash 段 | violations = 0 | 定位秒数并回退到保守设计 |

> **共享文件单写者**：`components/`、`cues.json`、`palette.json` 由主 agent 串行批准；子 agent 只写自己分区。

## II.9 风险与不做（Part II）

风险：场景脚本是任意 JS（沙箱：禁网络/禁 fs/白名单 API/超时强杀）；逐帧渲染成本（D15）；模型写的场景代码不可用（模板库 + 单帧自查 + "先静帧后动画"）；确定性被破坏（lint + 冻结 + 哈希闸）；闪光事故（D14 + 分段早测）；字体/歌词版权（OFL 白名单 + 用户提供）；效果库"只有名字没有实现"（每原语必须有单帧检查 + 单测）。

不做：复制参考作品镜头/文案/剪影；实时预览；审美评分；自动选曲/作词；移动端自适应；类型继承。

### II.13.4 流程（plan-first）

```
对话收集需求
  → brief_draft（结构化，字段与 CreativeBrief 对齐）
  → 用户确认                        [brief_confirmed]
  → 按类型 plan_schema 动态生成 plan
  → 校验（时长/段落连续/卡点与 BPM 一致/素材可得性/必填维度）
  → 确定性渲染 plan.md（不经 LLM 写 Markdown）
  → 用户确认或直接编辑结构化字段      [plan_confirmed]
  → plan 作为 StructureAgent 的上游输入（段落目的 / 画面类型 / 卡点）
  → 执行偏离规划时写回 plan 并记 plan_drift 事件
```

三条关键变化：

1. **plan 是执行的上游**，不再是执行结果的文档化。`StructureAgent` 必须读计划的段落目的与 `screen_kinds`——**如果 plan 为空/缺失，结构阶段应明确失败**，而不是退化回自由生成（否则"动态规划"又变成摆设）。
2. **规划书 Markdown 由 `plan_renderer.py` 渲染**（模板可由类型提供）。LLM 只负责写"段落目的、风险描述"这类**文本字段**，不负责排版。
3. **漂移留痕**：执行中改段/改时长/改画面类型 → 写 `plan_drift` 事件（谁改的、哪一段、原因），交付报告里可查。

### II.13.5 动态性的边界（防"动态=不可验收"）

| 边界 | 规则 |
|---|---|
| 维度必须有声明 | `plan_schema.required` 缺失 → 拒绝 `plan_confirmed` |
| 自定义维度要理由 | `custom_sections` 每项必填 `reason`；`custom_allowed=false` 时拒 |
| 段落必须连续 | `sections` 的 `t0/t1` 必须覆盖 `[0, target_duration_sec]`，不得重叠或留空（MV 用歌曲时长；其他类型用估算时长） |
| 卡点必须自洽 | 有 `beats` 时必须与音频 BPM/第 0 拍一致（与 C7 共用同一份 `grid`） |
| 时长必须可信 | `Σ(t1-t0)` 与 `target_duration_sec` 偏差 >10% → 告警；>25% → 拒绝确认 |
| 素材必须可得 | `material_strategy.gaps` 非空 → 必须在确认页显式展示，不许藏 |
| 旧数据必须能读 | 老 session 只有 scenes 无 plan → 走"由 scenes 反向生成 plan（标 `legacy: true`）"路径，不报错 |

### II.13.6 与主 agent（路线 C）的衔接

`PlanDocument.sections` 与主 agent 的 `PlanStep` 是同构的：`section → step`（目的、范围、验收口径）。因此：

- 需求 agent 产出的 plan 可**直接映射**为主 agent 的任务计划（不必二次生成）；
- 主 agent 的 `replan` 与 `plan_drift` 是同一套语义：改的是 plan，不是凭空改时间线；
- 这样"秘书型主 agent"与"需求 agent 的动态规划"不会变成两套互相打架的计划系统。

### II.13.7 验收（V52–V60）

| 编号 | 验收项 | 判定 |
|---|---|---|
| V52 | plan 由结构化对象渲染，同一 plan 两次渲染逐字节一致 | 单测（对比 sha256） |
| V53 | **字段漂移消除**：`CreativeBrief` 字段集 ⊇ prompt 声明产出的字段集 | 单测（集合断言）+ 一次真实 brief 落库检查 |
| V54 | 类型 `plan_schema.required` 缺项 → `plan_confirmed` 被拒 | 单测 |

# Part III 能否制作「一切」歌曲 MV / PV（覆盖审计）

## III.1 先定义什么叫"能制作"

避免空话，定三条判据，全部满足才算"能"：

| 判据 | 含义 |
|---|---|
| **J1 有渲染路径** | 画面能由本系统的渲染链产出（HyperFrames 全帧合成 / ffmpeg 合成 / 既有动画引擎） |
| **J2 有素材来源** | 所需素材能合法获得：程序化生成、**用户提供、或素材库检索到**。**关键是"可识别 + 可落位"，不要求系统自己生产** |
| **J3 有验收闸** | 能自动判断"做对了没有"（技术闸 + 类型指标），不靠人肉每帧盯 |

一条形式化判据（v1.1 修正）：

> **凡能写成「时间的纯函数 + 素材/资产输入」的片子，本系统理论上就能做。**
> 注意「素材输入」这一项——**素材本身怎么来的不计入边界**：真人拍摄的片段、手绘的逐帧、3D 渲染的序列，只要是**文件**，系统就能识别它、打标它、把它放到指定位置。系统的边界不是"素材从哪来"，而是"**能不能识别与落位**"。
> 真正的边界只有两条：**不能无中生有地生成素材**（要拍摄/要画/要建模时）、以及**不能交付非线性物**（交互式）。

## III.2 MV / PV 形态穷举与逐类判定

| # | 形态 | 主体素材 | 判定 | 缺什么 / 边界 |
|---|---|---|---|---|
| 1 | 排版/文字动画 MV（kinetic typography） | 字体 | **能** | 只需 C5 + 字体白名单 |
| 2 | 界面/UI 叙事 MV（参考样本） | HTML 构件 | **能** | C2 构件库 |
| 3 | 几何/生成艺术/程序化动画 | 代码 | **能** | C1 |
| 4 | 版画/印刷/拼贴风格 | 位图 + 代码 | **能** | C3 |
| 5 | 代码/终端/数据可视化 MV | 代码 + 数据 | **能** | C2 `console` + 既有 diagram |
| 6 | VJ loop / 抽象光效 / 音画同步 | 代码 | **能** | 需音频驱动参数（C7 扩展） |
| 7 | 歌词视频（lyric video，纯图形） | 字体 + 图形 | **能** | C5 + C7 |
| 8 | 混剪 AMV / MAD（用既有影像） | 他人影像 | ⚠️ **需素材** | C13 识别 + 落位；**授权由用户自证** |
| 9 | 静止画/一图流（插画 + 运镜） | 插画资产 | ⚠️ **需素材** | 运镜/摆动/景深我们能做；插画用户提供 |
| 10 | 手绘/赛璐璐动画 MV | 用户提供逐帧或成片段落 | ⚠️ **需素材** | **不需要我们"作画"**；C13 落位 + 卡点 + 与自绘画面混排 |
| 11 | 2D 角色骨骼动画 | 用户提供的绑定渲染片段 | ⚠️ **需素材** | 我们不做绑定；把它当成素材段落落位 |
| 12 | 3D CG / 粒子 / 真实光照 | 用户渲染序列 | ⚠️ **需素材** | 我们不做建模/渲染；同上 |
| 13 | 实拍真人 MV（演唱/舞蹈） | 用户拍摄 | ⚠️ **需素材** | 拍摄在用户侧；C13 按乐句/关键词/拍点落位 |
| 14 | 实拍 + 特效合成（去背/跟踪/roto） | 拍摄 + 合成 | ⚠️ **需素材** | 已有 `background_remove / face_detect`；跟踪/roto 由 G3 可选补 |
| 15 | 摄影/镜头语言主导（胶片质感） | 拍摄 | ⚠️ **需素材** | 调色/滤镜/节奏/卡点我们能做；"拍出来"在用户侧 |
| 16 | 演唱会/现场多机位 | 拍摄 | ⚠️ **需素材** | 多机位对齐 + 按拍点切换机位 |
| 17 | 多语言/卡拉OK/翻译字幕 MV | 字体 + 字幕 | ✅ **能** | 字幕与字体已具备 |
| 18 | 长曲/专辑连续/多结局（多版本） | 代码 | ✅ **能** | 分段渲染；受渲染预算约束（D15） |
| 19 | 交互式 MV（点击/分支） | 交互 | ❌ **不能** | 交付物是线性视频；可做"多版本"但不是交互 |
| 20 | 高动态频闪风格（故意闪） | 代码 | ❌ **不能** | 安全红线（D14 拒绝交付） |

**统计（20 类）**：✅ 能 **18**（自给自足 **9**：1–7、17、18 ＋ 需用户素材但系统可完成 **9**：8–16）｜❌ 不能 **2**（19 交互式、20 故意频闪）。

> v1.0 曾把 8–16 判为"不能/部分"，理由是"我们不会拍、不会画、不会建模"。**这个理由站不住**：素材存在时，系统的任务是**识别它、并按乐句与拍点放到该在的位置**——这正是 C13。判断标准从"素材谁生产"改成了"素材可不可识别与落位"。这是本轮最重要的修正。

## III.3 三条边界（v1.1 重写）

| 边界 | 具体含义 | 与 v1.0 的差别 |
|---|---|---|
| **B1 生成边界** | 系统不能**无中生有**地生成素材（不能拍摄、不能作画、不能建模） | v1.0 把它当成"不能做这类 MV"；**错**——素材存在时不受限，只在"素材不存在"时报 `material_gap` |
| **B2 交付形态边界** | 交付物是线性视频 | 交互式 MV 需要另做播放器/分支引擎，不在本期；可退化为"多版本导出" |
| **B3 审美边界** | 我们能判"技术合规"与"类型符合"，判不了"好不好听好看" | 不变；只能由人终审（V40 / 人工验收） |

**关键认知**：v1.0 把"素材从哪来"当成了系统边界，于是把拍摄/手绘/3D 类全划成"不能"。但你指出的对——**边界应该在"能不能识别并落位"**，而不在"素材是谁生产的"。底座其实早就有了：`content_index.py`（44KB 镜头级索引）、`content_query.py`（35KB 语义检索）、`content_semantic.py`、`scene_grounding.py`（13KB，NL→落位）。缺的只是把它们**接到 MV 工序上**（C13）。

## III.4 结论：能不能做「一切」

**能做 18/20 类；剩下 2 类不是能力问题，是定义与红线问题。**

「能做一切」在三条前提下成立，缺任何一条就不成立——这三条也是我们对外说话的边界：

| 前提 | 含义 | 不满足时 |
|---|---|---|
| **P1 素材存在** | 需要的素材是文件（用户提供、素材库、或程序化生成） | 报 `material_gap`，列缺口清单，不硬凑 |
| **P2 素材可识别可落位** | 系统能给它打标、按乐句/关键词/拍点放到位置 | 降级为"人工指定时间点"，仍能出片 |
| **P3 形态可写成纯函数** | 该形态的编排能被 `renderFrame(t)` 表达 | 交给 B2（交互式不做） |

### ✅ 能（18 类）

- **自给自足 9 类**：排版动画、界面叙事、生成艺术、版画拼贴、代码与数据、VJ 与光效、纯图形歌词视频、多语言字幕、长曲与多版本。
- **需素材 9 类**：混剪 AMV/MAD、静止画一图流、手绘/赛璐璐、2D 骨骼、3D CG、真人实拍、实拍+特效合成、摄影主导、演唱会多机位。
  → 我们负责**识别、落位、卡点、合成、字幕、安全闸**；素材与授权由用户提供。

### ❌ 不能（2 类）

- **19 交互式 MV**：交付物是线性视频（B2）。可以做"多版本/多结局导出"，但那不是交互。
- **20 故意频闪**：安全红线（B3 之外的安全约束，D14 拒绝交付）。

## III.5 「无中生有」若也要：两条可选能力线

v1.1 之后，这两条**不再必需**（只影响"没有素材时能不能自己造"）：

| 线 | 内容 | 何时才需要 | 成本 |
|---|---|---|---|
| **G1 图像生成（造型）** | 接入图像生成 provider（文生图/图生图/重绘）+ 角色一致性控制 + 生成物入素材库带种子留痕 | 用户没有插画/角色资产，期望系统画 | 8–12 人日（不含模型费用与合规） |
| **G2 3D / WebGL 合成** | WebGL 合成通道 + glTF 资产管线 + 相机/光照/景深入参 | 用户没有 3D 资产，期望系统建模渲染 | 15–25 人日 |

**G3（实拍素材治理）已并入 C13**（授权台账 + 跟踪/roto + 多机位对齐），属必需项，≈4–6 人日，计入 Part II 的 M 系列。

## III.6 对外承诺边界（写进产品口径）

| 承诺 | 不承诺 |
|---|---|
| 20 类 MV/PV 形态中 **18 类可交付**；其中 9 类可全自动（无需外部素材），9 类需用户提供素材 | 不承诺"无素材也能生成"（拍摄/作画/建模不在范围内，除非补 G1/G2） |
| 素材型：系统负责识别 → 打标 → 落位 → 卡点 → 合成，并对每个落位给依据 | 不代用户取得素材授权；授权不明素材不进成片 |
| 技术闸（确定性/拍点/闪光/类型指标）自动判定并可复现 | 不承诺"好不好看"——审美需人终审 |
| 交付六件套 + 可复现数字 | 不承诺一次即过；参考样本自身就是第 4 版 |
| 交互式 MV 不做（可做多版本导出） | 故意频闪不做（安全红线） |
