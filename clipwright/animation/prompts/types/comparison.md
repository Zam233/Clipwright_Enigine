# 对比（comparison）

## Intent

把两件事摆在同一屏上做对照，让差异一眼可见（不是各说一段）。

## Semantic constraints

- 左右两侧必须是同一维度的对照项（同一问题、两种答案）
- 不得使用输入里没有的数字；没有数字就不要编织数据
- 两侧字数尽量接近，长度差超过一倍时先压缩措辞而不是缩字号
- 节点文字必须能在旁白里找到依据；超过 18 字先摘要

## Composition

左右两栏 + 中央分隔（VS/→/对照标签）；每侧一条主句 + 至多一个补充词；顶部一行结论式小标题。

## Motion

左先右后错峰 0.2–0.4s 入场；分隔线先绘制、再由中心向两侧展开；末段保留 0.8s 静止供阅读。

## Anti-patterns

- 两侧内容不在同一维度
- 只换颜色不表达差异
- 长句塞进盒子导致压字

## Example

数据：旁白给出「对比两个事物 A vs B，渐变背景 + 逐元素入场」。
生成要点：3–5 个元素，主视觉居中偏上，一条主结论小标题；入场错峰 0.15–0.3s，
关键帧覆盖 ≥ 60% 片段时长，末段 0.6s 静止；不出现原文之外的事实。

## Style reference

以下视觉语言来自公开的代码动画风格库（341 种，按语义匹配本类型），只借用**构图/配色/节奏/入场方式**，内容与事实必须仍来自本片旁白：
- **F3 分屏对比**；画面：左边以前，右边现在，中间一条线。；关键词：分屏、对比、左右；参考做法：用代码（Canvas 2D）画一段"分屏对比"的动画：左边以前，右边现在，中间一条线

落笔要求：借用其动效语言，但元素内容必须能在本段旁白里找到依据；不引入参考图里的示例数据与文案。
