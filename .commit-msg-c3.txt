feat(agent-c3): 管线降级为能力 + AGENT_MODE 双轨 + 老 API 兼容

C 不等于删管线：常规套路用一条调好的流水线做，比让 agent 现编计划更省钱。
C3 把它包成 Kernel 可调用的一个 Step，并用开关保证 off 模式行为不变。

新增：
1. services/pipeline_capability.py — run_pipeline 能力
   - 双轨门禁：agent_mode != on 直接拒（off 走老 API，shadow 只规划不执行）
   - 预算前置：与老入口同一把闸（services.budget.check_budget），换调用方不绕闸
   - 参数合并：Step 参数优先，extra_params 叠加 duration_sec 等
   - 返回结构化指标（tracks/clips/duration/output_path），供 Kernel 观察与成本对比
   - 结果按 task 缓存，供老 /result 兼容层回读（随 C7 老入口退役一起删）
2. config + config_schema — agent_mode（off/shadow/on，默认 off）+ 三道闸数值项
   （agent_max_turns/agent_max_tool_calls/agent_max_wall_sec），设置页可直接改
3. api/pipeline.py — 双轨兼容层
   - run-async 在 agent_mode=on 时转 Task 并返回兼容体
     （pipeline_id = task id，附带 task_id/mode=agent/status=started）
   - status / result / cancel 增加 Task 回退（status 映射、last_result 回读、取消转 Kernel）
   - owner 登记：task id 也写进 _pipeline_owners，jwt 模式下不自伤
   - 顺手修一个旧 bug：get_pipeline_status 里 `_load_result_from_mongo` 漏了 await
     （拿到 coroutine 就 .get，Mongo 回退路径必然 AttributeError）
4. Kernel 接线：default_executor 现在真的把 run_pipeline 转给能力

测试：新增 9 条（双轨门禁/预算/参数合并/失败透传/off 不建 Task/
on 返回 task id/status+cancel+result 兼容/内核接线）；后端全量 3476 passed
